# Гибридная проверка: мейджоры + Яндекс

Что изменилось в мониторе и почему. Коротко: **перестали терять треки**.

---

## Схема

```
Shazam Top 200 Россия  →  дельта со вчера  →  новые треки
                                                  ↓
                                    ┌─────────────┴─────────────┐
                                    │  ФИЛЬТР 1: мейджоры       │
                                    │  лейбл из iTunes          │
                                    └─────────────┬─────────────┘
                                                  ↓ не мейджор
                                    ┌─────────────┴─────────────┐
                                    │  ФИЛЬТР 2: Яндекс         │
                                    │  прямой API с токеном     │
                                    └─────────────┬─────────────┘
                                                  ↓
                                          Telegram-алерт
```

Никаких Spotify, kworb и прочего — только эти два фильтра.

---

## Главный принцип: лучше лишнее, чем потерянное

Лишний трек в алерте человек уберёт руками за секунду. Трек, который не
доехал, он не увидит никогда. Поэтому вся логика перекошена в сторону
«показать».

**Молчим ровно в двух случаях:**
- Яндекс подтвердил, что трек у него есть;
- лейбл однозначно мейджорский.

Всё остальное — включая «не смогли проверить» — уходит в Telegram с пометкой.

### Что было раньше

В алерт проходил только статус `verified_missing`. Статусы `uncertain`,
`not_confirmed`, `error` оседали в `pending` и исчезали. На живом пуле из
10 треков таких было **6**, причём минимум 2 из них — настоящие новинки.

---

## Фильтр 1: мейджоры

Лейбл берётся из поля `copyright` альбома в iTunes, сверяется со списком
алиасов Universal / Sony / Warner.

**Что починено.** Короткие алиасы (`ada`, `capitol`, `verve`, `nonesuch`,
`emi`) ловились внутри названий независимых лейблов. Ошибочно блокировались:

| Лейбл | Определялся как | Теперь |
|---|---|---|
| Ada Music Group | Warner ❌ | пропускается ✅ |
| Capitol Hill Records | Universal ❌ | пропускается ✅ |
| Verve Coffee Records | Universal ❌ | пропускается ✅ |
| Nonesuch Explorer | Warner ❌ | пропускается ✅ |

Теперь для неоднозначных алиасов нужно либо точное совпадение всей строки
(`ADA`, `EMI`, `Capitol`), либо упоминание семьи рядом
(`Warner Music Group / ADA`). Настоящие мейджоры по-прежнему ловятся — 16 из 16.

---

## Фильтр 2: Яндекс

**Было:** iTunes → song.link → Musicfetch (URL) → Musicfetch (ISRC).
Четыре шага, ни один не разговаривает с Яндексом — ищется *упоминание*
Яндекса на чужой странице. Плюс Musicfetch платный (от $50/мес), и без него
статус `verified_missing` недостижим вообще, то есть алертов не будет никогда.

**Стало:** прямой запрос к API Яндекса своим токеном — `yandex_direct.py`.

Замер на одном пуле:

| | старая цепочка | прямой API |
|---|---|---|
| Решено верно | 4 из 10 | **14 из 14** |
| Нерешённых | 6 | 0 |
| Время на трек | 3–6 с | **0.3–0.7 с** |
| Стоимость | от $50/мес | бесплатно |

### Три исхода вместо двух

```
PRESENT  — Яндекс ответил, трек есть   → молчим
ABSENT   — Яндекс ответил, трека нет   → в алерт
UNKNOWN  — не ответил / сомнительно    → В АЛЕРТ с пометкой «глянь руками»
```

`UNKNOWN` в алерт — сознательное решение. Именно здесь раньше терялись треки.

### Что умеет сверка

- **Транслитерация.** «Пыяла — АИГЕЛ» на Яндексе лежит как «Пыяла — AIGEL».
  Без транслита — разные строки, трек терялся.
- **Версии и ремиксы.** «Blinding Lights (Remix)» считается присутствующим,
  если базовый трек на Яндексе есть. Отрезаются `Slowed`, `Sped Up`,
  `Remastered`, `Radio Edit` и прочее.
- **Соисполнители.** В чарте «HUGEL, Imael Angel & Ultra Naté», на Яндексе
  просто «HUGEL». Склейка целиком давала 66% — ниже порога, трек уезжал в
  `UNKNOWN`. Теперь название и артист сверяются раздельно: 100%.
- **Чужие артисты не склеиваются.** «One Dance» у Drake и у Coldplay —
  разные треки, в `PRESENT` не попадут.

## Запуск

```powershell
$env:YANDEX_TOKEN = "ваш токен"
$env:BOT_TOKEN    = "токен телеграм-бота"
$env:CHAT_ID      = "куда слать"
py -3.11 monitor.py
```

`MUSICFETCH_TOKEN` больше **не обязателен**. Если он задан — старая цепочка
останется запасным путём для случаев, когда Яндекс не ответил. Если нет —
такие треки просто уйдут в алерт с пометкой.

### Зависимости

```powershell
py -3.11 -m pip install -r requirements.txt
py -3.11 -m pip install yandex-music thefuzz python-Levenshtein
```

## Тесты

```powershell
py -3.11 -m unittest discover -s tests
```

81 тест. Ключевые для вашего требования:

| Тест | Что стережёт |
|---|---|
| `test_unverifiable_track_is_not_silently_dropped` | «не проверили» ≠ «выбросили» |
| `test_yandex_outcomes_only_silence_confirmed_presence` | молчим только при подтверждённом наличии |
| `test_indie_labels_with_major_sounding_words_pass` | «Ada Music Group» не мейджор |
| `test_real_majors_are_still_detected` | настоящие мейджоры всё ещё ловятся |
| `test_featured_artists_do_not_sink_the_match` | соисполнители не топят совпадение |
| `test_same_title_different_artist_is_not_present` | одинаковые названия ≠ один трек |
